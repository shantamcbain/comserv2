### Branch discipline (load-bearing — respect ownership)
- `main` / `master` — production-stable. Do not originate schema/Result-class/DB-table
  work here; that belongs on the `schema` branch. Never `git switch main` inside a worktree.
- `aisystem`, `ai`, `aichatsystem-*` — AI/voice code ownership.
- `schema`, `schema-*` — DB tables, Result classes, schema-compare authority.
- `Documentation` (this branch) — documentation structure, rendered `.tt` docs, and sync tooling.
- `InventoryAccounting`, `ENCY` — their own domains.

If a task crosses ownership (e.g. AI feature needs a new table), **build the AI side
reusing existing tables**; hand new-table/hand-DDL needs to the schema owner. Never
hand-write DDL — create/repair DB structure **only via the app schema-compare flow**.

## 2. Documentation system (the core of this role)

Comserv keeps its user/admin docs as **`.tt` files rendered in-app**, with parallel
**`.SUMMARY.md` / `.md` files for AI context**. The two are different audiences:

| Audience | Format | Location | Notes |
|---|---|---|---|
| Rendered web page | `.tt` with YAML `META` block | `Comserv/root/Documentation/<Module>/…` and `Documentation/<Module>/…` | Must use `var(--*)` theming; never hardcode colors |
| AI context (plain) | `.SUMMARY.md` (<2KB) | `Documentation/<Module>/SUMMARY.md` | Quick structured context for agents |
| Module index | `index.tt` | `…/<Module>/index.tt` | Rendered landing page with a `META` block |
| Changelog | per-entry `.inc` fragments | `Comserv/root/Documentation/changelog/entries/` | See §3 — never hand-edit root `CHANGELOG.tt` (it is a generated reader) |

### `.tt` page contract (required on every created/edited doc)
- **PageVersion header** (top of file):
  `[% PageVersion = 'path/file.tt,v 0.01 2025/MM/DD shanta Exp shanta ' %]`
  plus the debug-mode echo block:
  `[% IF c.session.debug_mode == 1 %][% PageVersion %][% END %]`
- **YAML `META` block** with at least `title`. Prefer also `description`, `category`,
  `roles`, `TemplateType`, `last_updated`, `page_version`, `site_specific`.
- **Theming:** use CSS variables — `var(--text-color)`, `var(--primary-color)`,
  `var(--link-color)`, etc. (from `base.css`). Pick the correct base template
  (`ApplicationTtTemplate` or `DocumentationTtTemplate`).
- **No `.md` under `Comserv/root/Documentation/`** for rendered pages — convert any
  stray `.md` there to `.tt`. (`.md` is acceptable only for AI-context stubs and
  session handoffs, per existing convention.)

### Automation that already exists
- `Documentation/script/sync-docs.sh` — scans Controllers/Models, refreshes the
  auto-detected controller index inside `CLAUDE.md` / `Documentation/SUMMARY.md`.
  Run `bash Documentation/script/sync-docs.sh --dry-run` to preview.
- Post-commit hook (`Documentation/script/post-commit-hook.sh`) runs the sync
  automatically on commits touching `.pm` files under `Controller/` or `Model/`.

## 3. Documentation compliance — DO THIS ON EVERY CHANGE

1. **Code/doc changes** → add a changelog **fragment**, do NOT hand-edit the
   root `CHANGELOG.tt` (that file is a *generated reader* rebuilt from the
   fragments). Create one file:
   `Comserv/root/Documentation/changelog/entries/YYYY-MM-DD-slug.inc`
   Format (matches every other entry):
   ```
   <div id="YYYY-MM-DD-slug" class="cl-entry">
   <h3>YYYY-MM-DD — Short title</h3>
   <p class="doc-body"><strong>What.</strong> …</p>
   <p class="doc-body"><strong>Why.</strong> …</p>
   <p class="doc-body"><strong>Files.</strong> <code>…</code></p>
   </div>
   ```
   This directory exists on **every branch**, so the note is visible everywhere
   and adding a file never collides on merge. The reader at
   `/Documentation/CHANGELOG` is generated by `Comserv::Util::Changelog`.
   Keep each entry specific: symptom, root cause, solution, files touched.
2. **Member / user how-to** → edit the stable `Documentation/guides/*.tt` (or the
   relevant module `index.tt`) **in place**; prefer improving existing docs over
   creating new ones.
3. **New module docs** → add an `index.tt` with a `META` block AND a sibling
   `SUMMARY.md` for AI context.
4. **Decision: `.tt` vs DB vs both** → made ad hoc per topic. Use the in-app
   documentation controller (`/Documentation/...`) for content that should render;
   use the `ency` documentation tables only when content is data-driven.
5. **Re-run the sync** after touching controllers/models:
   `bash Documentation/script/sync-docs.sh --dry-run` (then without flag if it
   would update the index).

## 4. Hard rules for AI assistants

- **Never replace or modify existing files without explicit permission.** Propose the
  change and explain its impact first (this is the standing `AI_ASSISTANT_GUIDELINES.tt`
  policy — it overrides "just fix it").
- **Perl module hygiene:** filename must match `package` declaration. Path
  `lib/Comserv/Controller/Foo/Bar.pm` ⇒ `package Comserv::Controller::Foo::Bar;`.
  Verify with the scan in AGENTS.md after creating/editing controllers.
- **Logging:** use `$self->logging->log_with_details($c, 'info', __FILE__, __LINE__,
  'method', "message")` — not bare `warn`/`print`.
- **Schema authority:** Result class is the source of truth. DB structure changes go
  through the app schema-compare; this DBIC version has **no `add_index`** — use
  `add_unique_constraint(name => [cols])`. Never hand-DDL.
- **Theming/compliance:** replace hardcoded colors with `var(--*)`; verify `.tt`
  renders across sites/themes.
- **Don't restart `:3001`** unless explicitly asked. Static asset changes (JS/JSON)
  apply on browser hard-refresh alone.
