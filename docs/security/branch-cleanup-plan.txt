IMPACT
- 49 extra branches are 49 extra places a leaked password lives; clones, forks and pull-request refs outlive any deletion.
- 94 local branches and 28 worktrees with no registry for 11 of them is how bots lose track of who owns what.
- Deleting branches does NOT: remove commits reachable from main or any other ref, remove other people's clones or forks, remove GitHub's
  cached commit pages or pull-request refs (refs/pull/*), or invalidate a password. It only shrinks what is easy to find.
  So password rotation (db-password-rotation-design.txt) is still required, and comes FIRST.

SOLUTION
Order matters:
 0. Rotate the database password (production first). Branch deletion is housekeeping after that, not a fix.
 1. Make the bundle backup (the script does it before any delete): git bundle create ~/.comserv/backups/branch-cleanup-<time>.bundle --all, verified,
    with a sha256 and a name/sha restore list. Keep one copy off the workstation. Do NOT back up as tags on GitHub: that would keep the leaked commits there.
 2. Push main only after the secret scan is clean (it is 157 commits ahead); then re-run the dry-run so "merged" is measured against the real origin/main.
 3. Delete the DELETE-merged-stale remote branches (14 today: 3dprinting, Filemanagement, Forager, Master, Production, ProductionV1.0.0, ProjectManagement,
    Proxmoxinterface, SiteSetup, Sitesetup, User, WorkShops, master, ve7tit). Names like Production/Master look important: Shanta confirms once.
    Each is fully contained in main, so no work is lost; the restore list lets any one be recreated.
 4. Unmerged (30 remote, 43 local): never auto-deleted. For each, the owner bot (suggested owner in the table below) answers one of: "already in main"
    (patch-id check below), "keep, here is why", "archive then delete". Names go into an approved list file; the script deletes only those, after the bundle.
 5. Registered and worktree branches: keep. Register or retire the 11 unregistered worktrees (Shanta decides; Code Guard lists them).
 6. Local clean-up: delete the 21 local merged-stale branches (same script, local section), `git worktree prune`, and remove the local_main remote
    (git remote remove local_main) so `git branch -r` shows only GitHub.
 7. Keep it clean (GitHub settings, Shanta applies in the web UI; verify afterwards):
    - Settings > General > "Automatically delete head branches" ON.
    - Settings > Rules (or Branches): ruleset on main: block force pushes and deletion; require status check "secret-scan / scan" (workflow is on codeguard,
      not on main yet); require PRs only if Shanta wants it, because bots commit directly to main today.
    - A second ruleset: restrict branch CREATION to main (so worktree branches cannot be pushed by accident). Matches Shanta's "only main is pushed".
    - Settings > Code security: Secret scanning ON and Push protection ON (both free for a public repo; check plan if private).
    - Optional: a monthly Code Guard sweep runs script/branch_cleanup.sh dry-run and files one todo if it lists anything.
 8. The generated delete list is a file of exact commands (the script writes it on every dry-run): `git push origin --delete <name>` per branch and
    `git branch -d <name>` per local branch. The script runs them one at a time and reports failures.

HOW THE SCRIPT BEHAVES
  script/branch_cleanup.sh                          dry-run: prints every branch with its category, the summary, writes the command file. Changes nothing.
  script/branch_cleanup.sh --stale-days 90          change the age cut-off (default 60)
  script/branch_cleanup.sh --keep-file F            extra names to never delete
  script/branch_cleanup.sh --approved-unmerged F    unmerged branch names the owner approved
  script/branch_cleanup.sh --execute                bundle all refs -> verify -> ask to type DELETE -> delete one by one. Aborts if the bundle fails.
  script/branch_cleanup.sh --execute --yes          no typed confirmation (use only with Shanta's explicit OK for that run)
  Never deletes: main, the remote default branch, any branch in worktrees.json or checked out in a worktree, any keep-file name, recent merged
  branches, or unmerged branches without an approved name. Never force-pushes or rewrites history.
  Verified: the self-test builds a throwaway bare repo and proves dry-run deletes nothing, a missing confirmation deletes nothing, merged-stale is
  deleted, unmerged/keep/recent are not, and an approved unmerged branch is deleted only when listed.

RISK / UNDO
- A deleted remote branch is recreated with: git push origin <sha>:refs/heads/<name> (shas are in the restore list); the bundle restores all refs:
  git bundle verify <file>; git fetch <file> '<name>:<name>'. Restore-list and bundle are mode 600 in ~/.comserv/backups.
- "Merged" means all its commits are ancestors of main. Squash-merged work looks unmerged (safe: it is kept), never the reverse.
- A bot may have a worktree whose branch you delete locally: the script refuses branches checked out in any worktree.
- Risk of a surprise: a deploy script or a person may reference an old branch such as Production. None of the CI workflows do; grep deploy docs once.
- Deleting remote branches does not clean main (28 files still hold the password), forks, clones, PR refs or GitHub caches: rotate the password.
