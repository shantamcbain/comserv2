BOT GIT IDENTITIES  (Code Guard for Shanta, 2026-10-24)

PROBLEM
Every commit showed "Zencoder <zencoder@workstation.local>" (global ~/.gitconfig), so it was
impossible to tell which bot or person made a change.

WHERE IT WAS SET
Only the global ~/.gitconfig (user.name / user.email). No repo, worktree, GIT_AUTHOR_*/GIT_COMMITTER_*
env var, Hermes config, Util/Git.pm or Admin/Git.pm override exists. Util/Git.pm runs plain
"git commit -m" inside the branch worktree, so it automatically uses per-worktree identity.

SOLUTION
extensions.worktreeConfig=true (in the main repo's .git/config) plus "git config --worktree user.*"
in each bot worktree. The identity is stored in <gitdir>/worktrees/<name>/config.worktree (main:
.git/config.worktree). Author and committer are both the bot. The global identity stays as fallback.

not made because it touches the app's commit flow.

ADD / CHANGE ONE
  git -C <worktree> config --worktree user.name  "Name"
  git -C <worktree> config --worktree user.email "id@workstation.local"
  git -C <worktree> var GIT_AUTHOR_IDENT        # verify

LIMITS
Identity is only a label, not authentication: anyone can set any name. Old commits are unchanged.
Merge commits made on main show the main identity. If Hermes or a script sets GIT_AUTHOR_* env vars,
those win over this config.

RISK / UNDO
Low. To undo one worktree:  git -C <worktree> config --worktree --unset user.name; ... --unset user.email
To undo everything:         git config --unset extensions.worktreeConfig   (per-worktree files are then ignored)
